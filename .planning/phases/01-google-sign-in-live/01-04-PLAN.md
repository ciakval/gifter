3. scripts/smoke.sh (bash, set -euo pipefail, executable): usage "scripts/smoke.sh BASE_URL [HOST]". When HOST is given, every request sends Host HOST and X-Forwarded-Proto https (simulating Caddy) and ORIGIN is https://HOST; otherwise ORIGIN is BASE_URL. Checks, each printing PASS or FAIL with a reason and exiting 1 on the first failure:
   (a) GET / returns 200 and the body contains action="/accounts/google/login/";
   (b) the GET / response carries a Strict-Transport-Security header that includes includeSubDomains;
   (c) GET /events/ returns 302 with Location /?next=/events/;
   (d) GET /login/ returns 404 and the body does not contain Django's debug-page phrase "Using the URLconf" (proves DEBUG is off);
   (e) GET /admin/ returns 404;
   (f) GET /static/vendor/bootstrap/bootstrap.min.css returns 200;
   (g) OAuth start: take the csrftoken value from the Set-Cookie header of (a) and the csrfmiddlewaretoken value from the HTML of (a); POST /accounts/google/login/ with form fields csrfmiddlewaretoken and next=/events/, sending the cookie as an explicit Cookie header (curl's cookie jar will not send a Secure cookie over plain http to the local container) plus Referer ORIGIN/ and Origin ORIGIN; expect 302 whose Location starts with https://accounts.google.com/, contains code_challenge_method=S256, and contains redirect_uri= followed by the URL-encoded ORIGIN/accounts/google/login/callback/; print one line "client_id=VALUE" extracted from that Location.
   Finish with the line "SMOKE OK". Use a mktemp directory for headers/bodies and remove it on exit.
4. scripts/container-smoke.sh (bash, set -euo pipefail, executable): builds the image as gifter:smoke from the repo root (docker build -q), then:
   (a) static image checks in a throwaway container: id -u is 1000, /app/.env does not exist, /app/data is empty, no file under /app ends in .sqlite3, and python reports django.VERSION major.minor == (6, 1);
   (b) creates a host data dir with mktemp -d and chmod 777 (portable for any host uid), starts container A detached on 127.0.0.1 port SMOKE_PORT (default 18000) mapped to 8000, with the data dir bind-mounted at /app/data and env SECRET_KEY (random, generated in the script), PUBLIC_HOSTS=gifter.remesh.cz, GOOGLE_CLIENT_ID=smoke-client-id, GOOGLE_CLIENT_SECRET=smoke-secret, DEBUG unset; waits up to 30 s for the port to answer;
   (c) asserts a plain request with Host gifter.remesh.cz and no X-Forwarded-Proto gets 301 with Location https://gifter.remesh.cz/;
   (d) runs scripts/smoke.sh against http://127.0.0.1:SMOKE_PORT with HOST gifter.remesh.cz;
   (e) persistence: docker exec container A to create a user with username smoke-persist through manage.py shell -c; remove container A; start container B with the same data dir and env; wait for it; assert via docker exec that the smoke-persist user exists, that docker logs of B contain "No migrations to apply", and that PRAGMA journal_mode on /app/data/db.sqlite3 (queried with python's sqlite3 inside the container) is wal;
   (f) a trap removes both containers and the data dir on any exit; print "CONTAINER SMOKE OK" at the end.
   The local port mapping exists only inside this test script; the deployable compose.yaml (Task 2) publishes nothing.
