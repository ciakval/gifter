# Plan 01-06: Public privacy page (publish prerequisite) and pipeline hardening

## Phase Goal

> ROADMAP `**Goal:**` (verbatim, not in user-story format): "Anyone with a Google account can sign in to Gifter at https://gifter.remesh.cz. The site runs on a cleaned-up Django 6.1 codebase that redeploys automatically from `main`." (No user story invented; run `/gsd-mvp-phase 1` to reframe if wanted.)

This is gap-closure plan 1 of 3 for the blocking gap in `01-VERIFICATION.md` (SC-2: a never-added Google account cannot sign in because the consent screen is still in Testing, and Google will not publish without a privacy policy link). This plan builds and tests the page. Plan 01-07 hardens the Google-only door. Plan 01-08 deploys, has the user publish the consent screen, and collects the human checks.

<objective>
Add a public, honest `/privacy/` page that Google's Branding step can point at. Link it from the footer of every page, so the landing page (the app home page for Google) links to it. Document the Branding fields and the optional `GIFTER_CONTACT_EMAIL` server setting. Close review findings WR-01 (`latest` tag from any branch) and WR-02 (mutable action refs, missing least-privilege permissions) in `deploy.yml`. Extend `scripts/smoke.sh` so every live check covers the privacy page.

Purpose: AUTH-01 / ROADMAP SC-2. A relative's Google account can only sign in once the consent screen is "In production", and Google requires a privacy policy URL on the app's domain first. OPS-03: tighten the image supply chain before relatives use the site.
Output: `gifter/templates/gifter/privacy.html`, `privacy` view and route, footer link, `gifter/tests/test_privacy.py`, `GIFTER_CONTACT_EMAIL` setting and `.env.example` line, updated DEPLOYMENT.md Google steps, hardened `deploy.yml`, and smoke checks (h) and (i).
</objective>
