<decisions>
Locked decisions (ROADMAP Phase 5 Notes, 2026-11-14), same numbering as 05-01:
- D-01 per (wish, event) threads; D-02 per (giftee, event) discussion; D-03 delete own yes, edit no; D-04 last-visit marker yes, notifications no; D-05 the giftee never learns a thread or comment exists; D-06 privacy policy EN and CS; D-07 delete_user (05-03); D-08 Czech for every string.
Planner choices:
- P-05 (discretion, narrow and documented exception to the standing rule "state changes only via POST"): opening a thread records the viewer's own read receipt (a ThreadVisit row) on that GET. "Since your last visit" cannot be known any other way without JavaScript. The write is limited on purpose: it happens only after the gate has passed (so never for the giftee, who gets a 404 first), it touches only the viewer's own ThreadVisit row, never a Wish, Event, Comment or any shared state, and tests pin each of these. It is the only write on a GET in the app.
- P-06 (discretion): markers appear only on the event page cards (and per comment on the thread page). No navbar badge and no count on the events list, so there is exactly one surface to keep clean of the giftee's own threads.
- P-07 (discretion): comments are hard-deleted (the row is removed). A thread left empty simply shows no count and no marker.
</decisions>
